## 何のためのサイトか（ここから外れない）

- 出発点は、東京国立博物館で実物の浮世絵を見た体験。「何百年も前にここで暮らした人々の目と技を通して見た、同じ東京」（ケーススタディ overviewText1）。
- 軸は「技法の変遷」。静止画のギャラリーでは「摺りの工程」と「色の重なり」は体感できないから Web にした（docs/SCOPE.md §2）。
- 浮世絵の多くは、美術館の額縁の中ではなく、町の人が日常で買った大量生産の刷り物だった。だから /timeline は画一的なグリッドではなく、有機的な並びにした（ケーススタディ timelineDesignText2）。
- 主役は、河野さんが Adobe Fresco で手で分けた版木のレイヤーと、9色の枠（墨→肌/紙）で見える「色が増えていく流れ」。

## 美術館サイトから借りたもの・借りなかったもの

調べたもの: Google Arts & Culture、The Met、Louvre、Guggenheim、ColBase（Figma の「参考 — 美術館のコレクションサイト」）、Mobbin（作品詳細のシート、日付ごとに区切る一覧、年へ移動するピッカー）。

| 借りた（探しやすさ） | 由来 | v2 での形 |
|---|---|---|
| 時間で並べ、好きな時代へ飛ぶ | Google A&C の「時代で並べる」、Reddit の年へ移動 | 上に固定した「時代のものさし」（串団子の点、押すと移動） |
| 作品に必ず題・作者を添える | The Met | 作品の下に題・作者。詳細は出典も |
| 入口を少数に絞る | Guggenheim | トップの「入口2つ」 |
| 分類ごとの入口 | Louvre | トップの「時代から探す」（9時代） |
| 元の縦横比で密に並べる | ColBase | 作品は切り抜かずに元の比率のまま |
| 作品を開いて詳しく見る | Google A&C（iOS）、DailyArt | PC は横から、SP は下から出るシート |

借りなかったもの: 白い額縁・均一なグリッド・学術的なメタデータの表・ガラスケースの距離感。この作品の根拠（庶民の刷り物、色の変遷が主役）を消してしまうため。そもそもデータに制作年・所蔵館・寸法はなく、色の比率は推定値（periodColors.js）なので、収蔵品のような厳密さは出せない。

## トップ（/v2）で足したもの

1. **入口2つ**（ヒーローと説明の直後）: 「版木の重なりを見る」「時代ごとに作品を見る」。ケーススタディに「文脈のないレイヤーアニメーションだけでは、初めての訪問者は戸惑う」と記録された課題への答え。
2. **9色の枠（技法の横に固定）**: 墨摺絵 1色 → 紅摺絵 3色 → 錦絵 9色。src/data/techniques.js の「その技法で加わった色」から計算（当て推量はしない）。新しく加わった色に ◆。トップの物語と /timeline の色の仕組みをつなぐ。SP は画面下の帯。
3. **時代から探す**（9時代の入口）: 年・出来事・色の枠・作品1点。押すと /v2/timeline のその時代へ。旧 /timeline は一覧まで約25画面かかった。
4. 手塗りの3つの技法の区間と、墨色の CTA（方向 A）はそのまま。

## 時代ごとの作品（/v2/timeline）

1. **導入**: 何が並んでいるか（9時代・45点、色が増える順）と、色の枠の読み方（◆＝初登場）。
2. **時代のものさし**: 1670〜1850 に串団子の点。今いる時代が大きくなる。近い年（1750/1765/1770）は年号を交互に一段下げる。
3. **時代ごとの区切り**: 番号・年・出来事・作家・色の枠（初登場の色に ◆ と名前）。長い背景（背景・技法・売られ方）は「この時代の背景を読む」を押したときだけ（interface-usability.md §C「情報を減らし、残りは開いたときだけ出す」）。
4. **作品の並び**: 元の縦横比のまま、5点ごとに少しずつずらす（店先に刷り物が並ぶ気軽さ）。固定パネルをやめたので、作品とパネルが重なる問題（旧版で 6/8）が構造上なくなる。
5. **詳細シート**: 大きな画像・題・作者・説明・出典（Wikimedia Commons / Ukiyo-e.org へのリンク）・前後の作品。Esc で閉じる、← → で移動。
6. **色が増えていく**（最後のまとめ）: 9時代の色の枠を縦に並べる。押すとその時代へ戻る。

暗い墨色の地（方向 A）はそのまま。

## 実装で直したこと（本番にも効く話）

- Wikimedia の原寸画像（1枚で数 MB）を45枚読んでいたため、後半の時代の画像が間に合わなかった。Commons の縮小版（`/thumb/…/500px-…`。Wikimedia は 330・500・960・1280 など決まった幅しか返さない）に変え、失敗したら原寸に戻す。45/45 読み込めることを確認。本番の /timeline の速度（Lighthouse 75）の改善にもそのまま使える。
